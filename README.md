# 投研大盘数据采集系统

采集投研分析所需的大盘数据，提供 **Web 可视化看板**（一键采集、失败重跑、接口监控、定时调度），同时保留命令行入口。统一导出 CSV / Excel。**ETF 口径为每个交易日（日频）**，宏观数据为月度。

## 一、采集范围与数据源

| 类别 | 具体指标 | 数据源 | 频率 |
| --- | --- | --- | --- |
| 货币与信贷 | M0、M1、M2、居民储蓄存款、人民币存款余额、人民币贷款余额 | 中国人民银行（akshare 封装） | 月度 |
| 货币与信贷 | 社会融资规模存量 | 央行金融统计数据报告（权威锚点）+ 社融增量插值 | 月度 |
| 外贸 | 出口额、进口额、进出口总额 | 海关总署（akshare 封装） | 月度 |
| 消费与物价 | 社会消费品零售总额（当月）、CPI、PPI | 国家统计局（akshare 封装） | 月度 |
| 景气与市场 | 制造业 PMI、非制造业 PMI | 国家统计局（akshare 封装） | 月度 |
| 景气与市场 | A 股总市值（沪深）、央行黄金储备 | 交易所 / 国家外汇管理局（akshare 封装） | 月度 |
| ETF | 每日份额（亿份）、单位净值（元）、规模（亿元） | 上交所 / 深交所官方份额 + 天天基金日净值 | **每个交易日** |

共 **17 个宏观指标（月度）+ ETF 日频数据**。每条记录带 `单位` 字段，不同指标单位不同。

> **重要说明**：央行官网统计数据**不包含 ETF 数据**，因此 ETF 数据来自交易所官方披露的每日份额，配合天天基金每日单位净值计算规模。

**口径说明**：
- **ETF 规模** = 份额(亿份) × 单位净值(元/份)，为计算值，与基金公司定期报告净资产可能有细微差异。
- **进出口**原始数据为千美元，已换算为**亿美元**。
- **社融存量**：akshare 无存量接口，采用「权威锚点 + 社融增量插值」——央行每月报告公布的月末存量为锚点（代码中 `SFR_ANCHORS` 可增补），锚点之间月份按增量分配。锚点月为央行权威值，其余为插值估算。

## 三、安装与运行

```bash
pip3 install -r requirements.txt

# 采集全部数据（ETF 按配置区间逐交易日 + 宏观）
python3 main.py

# 只采集 ETF 日频数据 / 只采集宏观数据
python3 main.py --etf-only
python3 main.py --macro-only

# 指定配置文件、覆盖导出格式
python3 main.py --config config.json --output-format excel

# 接口运维监控
python3 main.py --monitor-report    # 仅生成历史监控报告（不采集）
python3 main.py --retry-failed      # 重跑最近一个「有失败」批次的失败接口
```

## 四、配置说明

编辑 `config.json`：

```json
{
  "etf": {
    "codes": ["510300", "510050", "510500", "159915", "588000"],
    "start_date": "",
    "end_date": "",
    "default_trade_days": 20
  },
  "macro": { "start_date": "2024-01" },
  "output": { "formats": ["csv", "excel"] },
  "fetch": { "retry": 3, "retry_interval_sec": 2, "timeout_sec": 15 },
  "monitor": { "history_file": "output/monitor/interface_runs.jsonl" }
}
```

- **etf.codes**：要采集的 ETF 代码（6 位数字）。当前为主流宽基示例，**请替换为你的标的清单**。填 `[]` 则跳过 ETF 采集。
- **etf.start_date / end_date**：日频数据区间，格式 `YYYY-MM-DD`。两者留空时，`end_date` 取今天，`start_date` 取往前 `default_trade_days` 个交易日。
- **etf.default_trade_days**：留空日期时默认采集最近 N 个交易日，默认 20。N 越大，上交所逐交易日查询耗时越长。
- **macro.start_date**：宏观数据起始月份 `YYYY-MM`，留空取全部历史。
- **fetch**：网络重试次数、间隔与超时。单只 ETF / 单个交易日失败不会影响其余数据。
- **monitor.history_file**：接口调用历史（JSONL 追加写），记录每次调用的日期、状态、失败原因与重试次数；`--retry-failed` 依赖此文件定位失败接口。

## 五、接口运维监控与失败重跑

每次运行会为**每个采集接口**记录一条状态，追加写入 `output/monitor/interface_runs.jsonl`，并生成 `运维监控报告_*.xlsx`。主结果 Excel 也附 `接口监控` sheet（本次运行状态）。

**监控什么（逐接口）**

| 接口 | 覆盖 |
| --- | --- |
| 宏观 11 个 akshare 接口 | M0/M1/M2、存贷款、社融增量、进出口、社零、CPI、PPI、PMI、A股市值、黄金储备 |
| ETF 交易日历 | 交易日列表获取 |
| ETF 上交所份额 | 每个交易日一次调用（N 个交易日 = N 条记录） |
| ETF 深交所份额 | 日期区间一次调用 |
| ETF 天天基金净值 | 每只基金一次调用（N 只 = N 条记录） |

每条记录包含：**运行日期**、运行类型（full/retry）、接口键与名称、调用参数、状态（success/failed）、尝试次数、数据行数、**失败原因**、耗时。完整回答「哪天、哪个接口失败、为什么失败」。

**监控报告四个 sheet**

- `运行总览`：每批次调用数、成功/失败数、成功率、总耗时
- `失败明细`：逐条失败记录（失败日期、接口、原因、尝试次数）+ **重跑结果**标注
- `接口健康度`：每个接口累计调用/失败次数、成功率、最近失败日期与原因
- `调用明细`：全部调用记录，便于审计

**失败重跑机制**

```bash
python3 main.py --retry-failed     # 重跑最近一个「有失败」批次的失败接口
python3 main.py --monitor-report   # 单独生成监控报告
```

工作流程：

1. 从历史记录定位最近一个含失败的批次，列出每个失败接口的原因。
2. 宏观失败接口 → 只重采这些接口（按函数名精确重跑）。
3. ETF 份额失败 → 只重采失败的交易日/区间；ETF 净值失败 → 只补采失败基金的净值，份额沿用主数据，避免无谓重采引入新故障。
4. 重跑结果以非空字段覆盖合并到最新数据，并**统一重算规模**（份额 × 净值）；合并后写入新 CSV/Excel。
5. 重跑批次以新 run_id 记入历史，失败明细中标注「已重跑成功（日期/批次）」或「未重跑成功」。
6. 关键设计：即使之后又成功跑过一次，仍能重跑上一批次的失败接口（按最近含失败批次定位，而非最近批次）。

> 重跑只针对**临时性故障**（网络抖动、接口超时、502 等）。若接口变更导致字段缺失、或 ETF 代码本身无效，需修复代码或配置，重跑不会解决。

## 六、输出字段

**ETF 规模（日频）**：`基金代码`、`基金简称`、`交易市场`、`交易日期`、`份额(亿份)`、`单位净值(元)`、`规模(亿元)`、`数据源`、`采集时间`

- 交易市场：`SH` 上交所 / `SZ` 深交所
- 每个 ETF × 每个交易日一行，便于直接做时间序列分析和面板回归

**宏观数据（月度）**：`指标代码`、`指标名称`、`日期`、`数值`、`单位`、`同比(%)`、`环比(%)`、`数据源`、`采集时间`

指标代码对照：

| 代码 | 指标 | 单位 | 代码 | 指标 | 单位 |
| --- | --- | --- | --- | --- | --- |
| M0/M1/M2 | 货币供应量 | 亿元 | EXPORT/IMPORT/TRADE_TOTAL | 出口/进口/进出口 | 亿美元 |
| HH_DEPOSIT | 居民储蓄存款 | 亿元 | RETAIL_SALES | 社零(当月) | 亿元 |
| RMB_DEPOSIT/RMB_LOAN | 人民币存/贷款 | 亿元 | CPI/PPI | 物价指数 | 上年同月=100 |
| SFR_STOCK | 社融存量 | 亿元 | PMI_MFG/PMI_NONMFG | 制造业/非制造业PMI | 指数 |
| A_SHARE_MC | A股总市值 | 亿元 | GOLD_RESERVE | 央行黄金储备 | 万盎司 |

Excel 文件附 `口径说明` sheet，逐字段说明含义与单位。

## 七、实测验证结果

在 2026-11-22 环境实测通过：

- **宏观数据：545 行、17 个指标**（月度，起点 2024-01），零空值。最新值（2026-10）与官方一致：M2 359.06 万亿、社融存量 469.16 万亿、出口 4123.3 亿美元、进口 3070.5 亿美元、社零 46462.5 亿、CPI 100.7、PPI 105.7、制造业 PMI 49.3、A 股总市值 99.32 万亿、央行黄金 7830 万盎司。
- ETF 日频：**99 行**（5 只 ETF × 20 个交易日，2026-10-26 至 2026-11-20），份额、净值、规模三列**均无空值**。例如沪深300ETF华泰柏瑞 2026-11-20 份额 551.85 亿份、规模 2223.18 亿元。
- 接口监控：**39 次调用全部记录**（11 宏观 + 20 上交所份额 + 1 深交所份额 + 5 净值 + 2 交易日历），本次零失败；监控报告四个 sheet 与主 Excel「接口监控」sheet 均正常生成。
- 已验证：全量/单项采集、历史区间回补、交易日过滤、CSV/Excel 导出均正常；**失败重跑全链路通过**（注入 CPI 超时 + 净值 502 两条失败记录 → `--retry-failed` 重跑成功 → 报告标注「已重跑成功」、数据合并零空值）。
- 已知数据特性：深交所份额更新略滞后于上交所（本次深市标的止于 11-19，沪市止于 11-20）；深交所接口偶发瞬时断连，已被监控捕获并可重跑。

## 八、注意事项与扩展

1. **日频口径**：ETF 数据按交易日采集，非季末快照。若某标的在某交易日无数据（停牌、新上市等），该日不会出现该标的行。
2. **规模为计算值**：用份额 × 单位净值计算，适合做日频变化趋势分析；如需与基金公司披露的精确净资产对齐，请以定期报告为准。
3. **历史回补**：设置 `start_date` / `end_date` 即可回补任意区间；上交所按日查询，深交所一次请求返回整段区间，区间越长上交所耗时越久。
4. **社融存量**：锚点月为央行公布权威值，其余月份按社融增量插值。要更新权威锚点，在 `collectors/macro.py` 的 `SFR_ANCHORS` 字典中增补央行每月报告公布的月末存量即可。
5. **社零 2 月**：国家统计局对 1-2 月社零合并统计、不单独公布 2 月当月值，故该月无记录（属数据源正常缺失，已过滤空值行）。
6. 命令行仍可用：`python main.py` 全量采集，`--retry-failed` 重跑，`--monitor-report` 出监控报告。

## 九、Web 看板系统

### 启动

```bash
pip3 install -r requirements.txt
python3 web_app.py                 # 默认 0.0.0.0:8000（见 config.json 的 web 段）
python3 web_app.py --port 9000     # 覆盖端口
```

浏览器打开 **http://127.0.0.1:8000** 。服务启动后内置定时调度线程一并运行。

### 看板功能

| 区域 | 内容 |
| --- | --- |
| 顶部状态栏 | 服务器时间、定时调度状态、采集任务是否运行中 |
| 概览卡片 | 最近采集时间、宏观行数/指标数、ETF 行数/标的数、今日接口调用、历史失败累计（失败数红色高亮） |
| 采集控制台 | 「全量 / 仅宏观 / 仅 ETF / 重跑失败接口」四个按钮 + 实时日志终端（任务异步执行，前端轮询进度） |
| 接口监控看板 | 运行总览 / 失败明细（失败行红色高亮 + 重跑结果）/ 接口健康度 / 调用明细四个 Tab |
| 采集数据 | 宏观 / ETF 日频 / 输出文件三个 Tab，支持代码与日期筛选、文件下载 |
| 定时调度 | 界面勾选启用、设置每日时刻与采集范围，保存到 config.json |

### 关键机制

- **异步任务**：采集/重跑在后台线程执行，同一时刻只允许一个任务（避免并发写同一批文件），前端轮询 `/api/jobs/{id}` 实时显示日志与状态。日志只在 root 挂一次 handler，不重复。
- **单项采集保护**：仅采集宏观或仅采集 ETF 时，另一项沿用上次结果，避免空数据覆盖已有文件。
- **定时调度**：服务运行时按 `config.json` 的 `scheduler` 段每日指定时刻自动采集一次（同一天只触发一次），可在看板实时开关/改时间。任务与失败会在看板突出显示。
- **沿用文件存储**：不引入数据库，数据仍在 `output/`（CSV/Excel），监控历史在 `output/monitor/interface_runs.jsonl`。

### API 一览

`GET /api/status`、`/api/monitor/report`、`/api/monitor/failed`、`/api/data/macro`、`/api/data/etf`、`/api/files`、`/api/download?name=...`、`/api/jobs`、`/api/jobs/{id}`、`/api/scheduler`、`/api/health`；
`POST /api/collect`、`/api/retry`、`/api/scheduler`。交互式 API 文档见 `http://127.0.0.1:8000/docs`。
