# 投研大盘数据采集系统

采集投研分析所需的大盘数据，提供 **Web 可视化看板**（一键采集、失败重跑、接口监控、定时调度、分类导出），同时保留命令行入口。**SQLite 为唯一实时主存储**，CSV / Excel 为按需导出快照。**ETF 与指数口径均为每个交易日（日频）**，宏观数据为月度与季度混合。

## 一、采集范围与数据源

| 类别 | 具体指标 | 数据源 | 频率 |
| --- | --- | --- | --- |
| 货币与信贷 | M0、M1、M2、居民储蓄存款、人民币存款余额、人民币贷款余额 | 中国人民银行（akshare 封装） | 月度 |
| 货币与信贷 | 社会融资规模存量 | 中国人民银行调查统计司《社会融资规模存量统计表》 | 月度 |
| 外贸 | 出口额、进口额、进出口总额 | 海关总署（akshare 封装） | 月度 |
| 消费与物价 | 社会消费品零售总额（当月）、CPI、PPI | 国家统计局（akshare 封装） | 月度 |
| 景气与市场 | 制造业 PMI、非制造业 PMI | 国家统计局（akshare 封装） | 月度 |
| 景气与市场 | A 股总市值（沪深）、央行黄金储备 | 交易所 / 国家外汇管理局（akshare 封装） | 月度 |
| 中国增长 | 中国 GDP（季度绝对值、同比增长） | 国家统计局（akshare 封装） | 季度 |
| 美国增长与物价 | 美国 GDP、CPI、核心 CPI、PPI、非农新增就业 | FRED（BEA / BLS / 美联储） | 月度 / 季度 |
| 美国利率 | 联邦基金目标利率上限、下限（实际值） | FRED（美联储） | 月度（日频取最新） |
| ETF | 每日份额（亿份）、单位净值（元）、规模（亿元） | 上交所 / 深交所官方份额 + 天天基金日净值 | **每个交易日** |
| 指数 | 上证指数、沪深300、科创50、创业板指：开高低收、成交量、涨跌幅 | 新浪财经日线（akshare 封装） | **每个交易日（近一年）** |

共 **25 个宏观指标（17 项原指标 + 中国 GDP + 7 项美国指标，月度/季度混合）+ ETF 日频数据 + 4 个指数近一年日线数据**。每条记录带 `单位` 字段，不同指标单位不同。

日交易类别支持 6 类原始源：交易所概况、两融账户、全A个股快照、涨跌家数、成交集中度、沪深300风险溢价率（韭圈儿/funddb FED 差值直采）。`stock_zh_a_spot` 是实时接口，只有时间戳含完整日期或本地已收盘时才按当日落库，禁止把盘中值错标到上一交易日；历史交易日请使用 `tools/backfill_trade_snapshot.py` 按明确日期补数（北交所旧代码自动映射到 920 代码）。

> **重要说明**：央行官网统计数据**不包含 ETF 数据**，因此 ETF 数据来自交易所官方披露的每日份额，配合天天基金每日单位净值计算规模。

> **系统硬规则：不要清理采集的原数据。** `macro_observation` / `etf_observation` / `index_observation` 与 6 张交易 `*_raw` 表为采集层权威数据，不得在脚本、测试、修复、服务启动或批量运维中清理、删除、覆盖或先删后写。`clear_all()` 已排除全部采集数据；交易原始表永不进入任何清理白名单。观测表仅在用户通过 Web「数据清理」显式选择并二次确认后按口径删除。完整规则见 [`AGENTS.md`](AGENTS.md)。

**口径说明**：
- **ETF 规模** = 份额(亿份) × 单位净值(元/份)，为计算值，与基金公司定期报告净资产可能有细微差异。
- **指数**：默认采集近一年（365 天）交易日日线，标的与区间可在 Web「指数标的配置」中灵活调整；涨跌幅由相邻交易日收盘价环比计算，每只指数区间首日为空。
- **进出口**原始数据为千美元，已换算为**亿美元**。
- **社融存量**：直接抓取央行调查统计司《社会融资规模存量统计表》，逐月官方存量（万亿元→亿元）与官方增速作为同比；**已删除原「锚点 + 社融增量插值」逻辑**，官方表抓取失败时该指标本次不产出并记入失败明细，不做估算回退。实现见 `collectors/macro_sfr_stock.py`。
- **中国 GDP**：取统计局季度累计绝对值，日期映射为季末月（Q1→03、Q2→06、Q3→09、Q4→12），同比取自接口「国内生产总值-同比增长」。
- **美国 CPI / 核心 CPI / PPI**：FRED 指数水平；同比按上年同月、环比按上月计算（缺失月份自动跳过）。美国非农新增就业由 FRED 总就业人数月度差分得到，单位千人。
- **美国利率上下限**：取 FRED 联邦基金目标利率上限 `DFEDTARU` 与下限 `DFEDTARL` 的**实际值**；原始序列为日频，按月取月末最新有效值，单位 %。

## 三、安装与运行

```bash
pip3 install -r requirements.txt

# 首次从旧版 CSV/JSONL 迁移到 SQLite（幂等，可重复执行）
python3 migrate_to_sqlite.py

# 采集全部数据（宏观 + ETF 日频 + 指数近一年日线），写入 SQLite
python3 main.py

# 全量采集并统一指定日期范围（覆盖各类别配置默认值；留空则沿用配置）
python3 main.py --start 2024-01-01 --end 2024-06-30

# 只采集 ETF 日频 / 只采集宏观 / 只采集指数
python3 main.py --etf-only
python3 main.py --macro-only
python3 main.py --index-only

# 精确采集（按类别 + 代码 + 时间范围）
python3 main.py --collect-interface --category index --codes 000001,399006 --start 2026-01-01 --end 2026-11-20

# 指定配置文件、覆盖导出格式
python3 main.py --config config.json --output-format excel

# 接口运维监控
python3 main.py --monitor-report    # 从 SQLite 生成历史监控报告（不采集）
python3 main.py --retry-failed      # 重跑最近一个「有失败」批次的失败接口（含指数接口）

# 导出数据：Web 看板点击「导出宏观 / 导出 ETF / 导出指数 / 导出监控 / 导出全量」
# 对应 API：POST /api/export/macro|etf|index|monitor|full
```

## 四、配置说明

编辑 `config.json`：

```json
{
  "etf": {
    "codes": ["510300", "510050", "510500", "159915", "588000"],
    "start_date": "",
    "end_date": "",
    "default_trade_days": 20
  },
  "macro": { "start_date": "2026-11" },
  "storage": {
    "backend": "sqlite",
    "db_path": "output/market_data.db",
    "auto_export_on_collect": false
  },
  "output": { "formats": ["csv", "excel"], "keep_snapshots": 3 },
  "fetch": { "retry": 3, "retry_interval_sec": 2, "timeout_sec": 15 },
  "monitor": { "history_file": "output/monitor/interface_runs.jsonl" }
}
```

- **storage.backend**：`sqlite` 为实时主存储；`file` 仅用于旧版回滚。
- **storage.auto_export_on_collect**：默认 `false`，采集只写 SQLite；文件导出按需触发。
- **etf.codes**：要采集的 ETF 代码（6 位数字）。**注意：ETF 配置与上市日期已迁入 SQLite，config.json 仅作镜像**；以后以 Web「ETF 标的配置」或 `/api/etf/config` 为准。填 `[]` 则跳过 ETF 采集。
- **etf.start_date / end_date**：日频数据区间，格式 `YYYY-MM-DD`。两者留空时，`end_date` 取今天，`start_date` 取往前 `default_trade_days` 个交易日。
- **etf.default_trade_days**：留空日期时默认采集最近 N 个交易日，默认 20。N 越大，上交所逐交易日查询耗时越长。
- **index.codes**：要采集的指数代码，支持 `000001`（上证指数）、`000300`（沪深300）、`000688`（科创50）、`399006`（创业板指）。**指数配置已迁入 SQLite，config.json 仅作镜像**；以后以 Web「指数标的配置」或 `/api/index/config` 为准。
- **index.lookback_days**：采集范围，近 N 天（默认 365 = 近一年）；也可用 `start_date / end_date` 覆盖。
- **macro.start_date**：宏观数据起始月份 `YYYY-MM`，留空取全部历史。
- **fetch**：网络重试次数、间隔与超时。单只 ETF / 单个交易日 / 单个指数失败不会影响其余数据。
- **monitor.history_file**：旧版接口调用历史（JSONL），迁移后保留只读基线；实时监控已写入 SQLite 的 `interface_run` 表。

### SQLite 主存储与业务主键

| 表 | 业务主键 | 示例 |
| --- | --- | --- |
| `macro_observation` | `{指标代码}_{YYYYMM}` | `M2_202610` |
| `etf_observation` | `{6位基金代码}_{YYYYMMDD}` | `510050_20261020` |
| `index_observation` | `{6位指数代码}_{YYYYMMDD}` | `000001_20261120` |
| `interface_run` | `{run_id}_{接口键}_{运行时间}_{序号}` | `20261122_201814_interface_macro.fred_DFEDTARU_20261122_201814_001` |
| `collection_stat` | `{run_id}\|{类别}\|{细分代码}` | `20261122_201814_full\|ETF\|510050` |
| `etf_config` | `main` | 代码清单、上市日期、日期区间、默认交易日数 |
| `index_config` | `main` | 指数代码清单、日期区间、回看天数 |
| `meta` / `export_log` | key / id | 迁移标记与导出记录 |

所有业务写入均使用 `ON CONFLICT(biz_key) DO UPDATE`，因此全量采集、精确采集、失败重跑都不会产生重复行。

## 五、接口运维监控与失败重跑

每次运行会为**每个采集接口**记录一条状态，写入 SQLite 的 `interface_run` 表；Web 看板直接查询该表。**不再自动生成** `运维监控报告_*.xlsx`，可在「接口监控看板」点击「导出监控」按需生成（含口径说明）。

**监控什么（逐接口）**

| 接口 | 覆盖 |
| --- | --- |
| 宏观 11 个 akshare 接口 | M0/M1/M2、存贷款、社融增量、进出口、社零、CPI、PPI、PMI、A股市值、黄金储备 |
| ETF 交易日历 | 交易日列表获取 |
| ETF 上交所份额 | 每个交易日一次调用（N 个交易日 = N 条记录） |
| ETF 深交所份额 | 日期区间一次调用 |
| ETF 天天基金净值 | 每只基金一次调用（N 只 = N 条记录） |

每条记录包含：**运行日期**、运行类型（full/retry）、接口键与名称、调用参数、状态（success/failed）、尝试次数、数据行数、**失败原因**、耗时。完整回答「哪天、哪个接口失败、为什么失败」。

**详细失败原因**：每条失败记录同时给出四要素——**标的**（受影响标的，如 `510050, 510300`；旧记录会从接口/参数推断为「上交所全部ETF(日期)」等）、**失败原因**（异常类型/消息、HTTP 状态、URL）、**调用参数**（接口实际请求参数）、**响应**（接口返回片段；空数据场景也会记录响应内容）。结构化文本形如 `标的=… | 失败原因=… | 参数={…} | 响应=…`，出现在重跑启动日志、监控「失败明细」的**失败详情**列与单条重跑日志中。

**监控报告五个 sheet**

- `运行总览`：每批次调用数、成功/失败数、成功率、总耗时
- `失败明细`：逐条失败记录（失败日期、接口、原因、尝试次数）+ **重跑结果**标注 + **任务ID**（在 Web 看板该行点击「重跑此条」可按该 ID 单独重跑）+ **失败详情**（标的 / 失败原因 / 参数 / 响应 四要素）
- `接口健康度`：每个接口累计调用/失败次数、成功率、最近失败日期与原因
- `调用明细`：全部调用记录，便于审计
- `采集量统计`：每次采集按**类别口径（宏观/ETF/指数）+ 细分口径（指标/基金/指数代码）**的入库行数，写入 SQLite `collection_stat` 表，同批次同代码覆盖更新

**调用参数与失败原因**：每条记录的参数不再只有时间——宏观含 `interface`（akshare 函数名 / FRED 序列）、`source`（数据源）、FRED 的 `series_id` 与 `url`；ETF 含 `market`、`url`、`sqlId`/`catalog_id`/`jjlb` 等交易所请求参数；指数含 `symbol`、`interface`、`source`、`lookback_days`。失败原因为结构化文本：`异常类型: 消息 | HTTP 状态 | URL | 响应片段 | 补充上下文`（HTTP 接口自动提取响应状态码与片段）。

**失败重跑机制**

```bash
python3 main.py --retry-failed     # 重跑最近一个「有失败」批次的失败接口
python3 main.py --monitor-report   # 单独生成监控报告
```

工作流程：

1. 从历史记录定位最近一个含失败的批次，列出每个失败接口的原因。
2. 宏观失败接口 → 只重采这些接口（按函数名精确重跑）。
3. ETF 份额失败 → 只重采失败的交易日/区间；ETF 净值失败 → 只补采失败基金的净值，份额沿用主数据，避免无谓重采引入新故障。
4. 重跑结果以非空字段覆盖合并到最新数据，并**统一重算规模**（份额 × 净值）；合并后写入新 CSV/Excel。
5. 重跑批次以新 run_id 记入历史，失败明细中标注「已重跑成功（日期/批次）」或「未重跑成功」。
6. 关键设计：即使之后又成功跑过一次，仍能重跑上一批次的失败接口（按最近含失败批次定位，而非最近批次）。

**按条重跑（监控失败明细）**：Web 看板「接口监控看板 → 失败明细」Tab 中，每条失败记录都有稳定「任务ID」（接口键 + 规范化参数生成的哈希，参数顺序无关）。点击该行「重跑此条 / 再次重跑」按钮，仅重跑这一条失败任务（相同接口与参数），不影响其它失败项；重跑任务同样以新 run_id 记入监控并在该行标注结果。对应后端：`POST /api/retry/task`（`{"task_id": "..."}`）。控制台的「批量重跑失败」仍是重跑最近批次全部失败项。

> 重跑只针对**临时性故障**（网络抖动、接口超时、502 等）。若接口变更导致字段缺失、或 ETF 代码本身无效，需修复代码或配置，重跑不会解决。

## 六、输出字段

**ETF 规模（日频）**：`基金代码`、`基金简称`、`交易市场`、`交易日期`、`份额(亿份)`、`单位净值(元)`、`规模(亿元)`、`数据源`、`采集时间`

- 交易市场：`SH` 上交所 / `SZ` 深交所
- 每个 ETF × 每个交易日一行，便于直接做时间序列分析和面板回归

**指数日线（近一年交易日）**：`指数代码`、`指数名称`、`交易日期`、`开盘价`、`最高价`、`最低价`、`收盘价`、`成交量`、`涨跌幅(%)`、`数据源`、`采集时间`

- 默认近一年（365 天），每个指数 × 每个交易日一行；涨跌幅为环比计算值，区间首日为空。

**宏观数据（月度/季度/会议混合）**：`指标代码`、`指标名称`、`日期`、`数值`、`单位`、`同比(%)`、`环比(%)`、`数据源`、`采集时间`

| --- | --- | --- | --- | --- | --- |
| M0/M1/M2 | 货币供应量 | 亿元 | EXPORT/IMPORT/TRADE_TOTAL | 出口/进口/进出口 | 亿美元 |
| HH_DEPOSIT | 居民储蓄存款 | 亿元 | RETAIL_SALES | 社零(当月) | 亿元 |
| RMB_DEPOSIT/RMB_LOAN | 人民币存/贷款 | 亿元 | CPI/PPI | 物价指数 | 上年同月=100 |
| SFR_STOCK | 社融存量 | 亿元 | PMI_MFG/PMI_NONMFG | 制造业/非制造业PMI | 指数 |
| A_SHARE_MC | A股总市值 | 亿元 | GOLD_RESERVE | 央行黄金储备 | 万盎司 |

## 八、注意事项与扩展

1. **日频口径**：ETF 数据按交易日采集，非季末快照。若某标的在某交易日无数据（停牌、新上市等），该日不会出现该标的行。
2. **规模为计算值**：用份额 × 单位净值计算，适合做日频变化趋势分析；如需与基金公司披露的精确净资产对齐，请以定期报告为准。
3. **历史回补**：设置 `start_date` / `end_date` 即可回补任意区间；上交所按日查询，深交所一次请求返回整段区间，区间越长上交所耗时越久。
4. **社融存量**：仅采用央行调查统计司《社会融资规模存量统计表》官方值；无插值、无锚点补估。央行按年发布存量表（2016~2026 已验证），精确采集会按请求区间自动抓取对应年份的表并合并，不会再只取最新一年；2015 年表为季末口径，映射为 03/06/09/12 月。无需手工维护锚点字典。
5. **社零 2 月**：国家统计局对 1-2 月社零合并统计、不单独公布 2 月当月值，故该月无记录（属数据源正常缺失，已过滤空值行）。
   **社零环比口径**：`RETAIL_SALES` 的 `环比(%)` **不是** akshare 接口的未季调名义环比（当月÷上月−1，受春节/黄金周影响 ±10%，口径严重误导），而是采集时自动抓取**国家统计局最新一期社零新闻稿「附注 → 环比数据修订」表的官方季调环比**（通常 ±1% 以内，如 2026-10 = 0.02%、2026-09 = 0.34%）。统计每月会回溯修订最近约 13 个月，系统按最新一期覆盖并在 `数据源` 标注「国家统计局（季调环比）」；超出回溯窗口的更早月份保留接口原值。实现见 `collectors/macro_sa_mom.py`，抓取失败时降级保留原值并告警、不影响采集。
6. 命令行仍可用：`python main.py` 全量采集，`--retry-failed` 重跑，`--monitor-report` 出监控报告。
7. **请求节流**：`config.json` 的 `fetch.min_interval_sec`（默认 1.2s）与 `fetch.jitter_sec`（默认 0.5s）控制相邻外部接口请求的最小间隔与随机抖动，用于规避交易所接口（尤其深交所）对密集请求的反爬断连；设为 0 可关闭。接口失败时，监控记录的失败原因会附带「响应片段」与「受影响标的」，便于定位。
8. **文件导入**：支持把 Choice 导出的「份额与规模_<代码>.xlsx」作为 ETF 采集数据导入 SQLite（自动换算 份/元 → 亿份/亿元，按规模÷份额反推净值）。**单次最多 10 个文件**，超过直接拒绝、不写入数据。命令行 `python main.py --import-files <文件或目录>`，或在看板「采集控制台」的文件导入区上传；详见 `导入说明_Choice份额与规模.md`。
9. **基金代码清洗**：深交所部分交易日导出的 xlsx 中基金代码带尾随空格（如 `159629  `），采集器在解析与合并前统一 `.strip()` 并补零，避免按标的代码匹配时整批丢失导致当日份额缺失。上交所解析同样做防御性清洗。
10. **配置权威源**：ETF/指数的采集范围配置以 **SQLite 为权威源**，`load_config()` 用 SQLite 值覆盖 `config.json`；代码中的兜底默认值集中定义于 `storage.DEFAULT_ETF_CONFIG` / `DEFAULT_INDEX_CONFIG`（不再散落硬编码）。启动时自动把历史遗留的旧默认值（ETF 20 交易日、指数 365 天）迁移为新默认，用户显式设置的值不受影响。默认采集范围均为**最近一个已结束交易日**。

### 关键机制

- **异步任务**：采集/重跑在后台线程执行，同一时刻只允许一个任务（避免并发写同一批文件），前端轮询 `/api/jobs/{id}` 判断状态；日志由全局实时流统一渲染，避免重复。
- **实时监控 · 实时日志**：常驻轮询 `/api/live-logs`（按 `after=序号` 增量拉取），把**定时调度、后台采集、手动任务、导入/重跑**等所有线程的日志统一显示在采集控制台右侧，环形缓冲**保留最近 5000 行**（`LIVE_LOG_LIMIT`）；定时调度日志带「【定时调度】」前缀便于辨识。单行滚动条显示最新日志，点击可展开完整日志，保持自动滚动，可暂停或一键回到底部。日志 handler 只在 root 挂一次，不重复。
  - **逐步明细**：采集全程分步骤编号输出——调度器「步骤 1/5 触发 → 2/5 提交 → 3/5 采集 → 4/5 入库 → 5/5 完成」，并给出判定原因（未启用/未到点/今日已触发/任务占用）；ETF 采集以树形展开每一环节：区间锚定 → 上市日期逐只解析（`├/│/└`）→ 交易日历 → 上交所逐交易日进度 → 深交所区间查询 → 天天基金净值逐只 → 合并统计（忽略上市前记录/净值缺失数）；入库再分 a 保存监控 / b 写业务表 / c 采集量统计。每一步都带标的数、日期、行数，便于实时掌握进度与定位卡点。
- **单项采集保护**：SQLite 按业务主键 upsert；精确采集仅采单一类别/指标时，其它类别数据保持库中原样，不会被空 DataFrame 覆盖。
- **全量采集日期范围**：控制台全量采集可指定起止日期（默认当天，支持一键重置），后端用该范围统一覆盖宏观、ETF、指数三类的配置日期；`POST /api/collect` 的 `start` / `end` 为可选字段，留空则沿用 `config.json` 各类别默认值。命令行对应 `python main.py --start ... --end ...`。
- **日期区间兼容**：采集数据默认近一个月（近1月/近1年/近5年快捷切换），其余日期控件默认当天；前端统一传 YYYY-MM-DD，宏观采集与查询自动按月截取为 YYYY-MM。
- **交易日期排序**：采集数据的「日期 / 交易日期」表头可点击切换升序（▲）/降序（▼），默认降序（最新在前）；排序在后端分页层完成，`/api/data/{macro,etf,index}` 支持 `order=asc|desc` 参数。
- **定时调度**：服务运行时按 `config.json` 的 `scheduler` 段每日指定时刻自动采集一次（同一天只触发一次），可在看板实时开关/改时间；采集完成后自动触发派生指标**增量**重算（步骤 6/6），任务与失败会在看板突出显示。
- **派生重算 · 增量优先**：定时调度步骤 6/6 按本次 `run_id` 写入 `macro_observation` 的原始 `(代码, 月份)` 识别变更范围，经依赖映射（差分需上月、同比需去年同月、二阶差分需去年同月新增）推导受影响的派生 `(指标, 月份)`，只对这些目标计算并按 `biz_key` 幂等 **upsert**，不删全表、不对全量历史重复计算；派生表为空（首次）时自动回退全量建立基线。看板「重新计算」按钮为**手动兜底**：不带参数时仍全量重算 + `replace_derived()` 整表替换（清理陈旧口径行），可带 `month`/`code` 做局部重算。
- **数据处理模块**：派生结果写入 `derived_indicator` 表，`biz_key = derived_<code>+<YYYYMM>` 幂等 upsert；计算规则集中在 `processors/derived.py`，只读 `macro_observation`。主触发为**定时调度（增量）**，看板「重新计算」按钮仅为手动兜底（全量/局部）。顶部导航切换「采集系统 / 数据处理 / 数据看板」，三模块共用实时日志与存储。
- **数据看板**：装配逻辑在 `processors/dashboard.py`，只读 `derived_indicator` / `macro_observation` / `index_observation` / `etf_observation`，不写业务表。看板内「宏观指标 / ETF 维度」分 Tab 渲染，仅渲染当前 Tab，避免 ECharts 在隐藏容器中取不到宽度。指数为日频，图⑤自动取**月末最后一个交易日收盘**；ETF 变化先在全量历史上按基金代码计算环比，再按标签（汇金/黄金）与交易日窗口汇总，避免窗口首日被误判为无基准。前端使用本地 `static/echarts.min.js`，无需外网。
- **黄金当月新增换算**：央行黄金储备单位为**万盎司**，1 万盎司 = 10⁴ 盎司 × 31.1034768 克/盎司 ÷ 10⁶ 克/吨 = **0.311034768 吨**，即 `(当月−上月)万盎司 × 31.1034768 ÷ 100`；不可用 ÷10⁴（会缩小 100 倍）。2015-06 的 3389→5332 万盎司是一次性披露口径重述（+604 吨），非当月增持，规则中按 `|增量|≥100 吨` 视为口径跳变并剔除。
- **长周期历史补全**：`macro_rmb_loan` / `macro_rmb_deposit` 接口仅返回近 30 个月，`collectors/macro_long_history.py` 用可回溯到 2008 的「新增信贷」（当月新增递推重建贷款余额）与可回溯到 1993 的「货币供应量表·储蓄存款」补全长周期；社零 1-2 月统计局合并发布、无当月值，用累计同比补同比、累计差分补当月值。补全后：**人民币贷款当月新增 / 社零同比回溯至 2008，居民存款同比多增回溯至 2001**，满足近 10 年看板需求。手动全量重算派生时 `replace_derived()` 全量替换，清理旧口径残留行；定时增量重算则按变更范围 upsert。
- **SQLite 主存储**：业务数据、接口监控、ETF 配置与上市日期、指数配置均在 `output/market_data.db`；旧 CSV/JSONL 保留只读作为迁移与回滚基线。
- **分类导出**：采集只写库不生成文件；按需导出宏观 / ETF / 指数 / 接口监控，每个 Excel 都含「口径说明」Sheet，CSV 同步生成独立口径说明文件；全量导出打包 ZIP（含宏观/ETF/监控三类，指数可单独导出）。
- **口径化清理**：`POST /api/clean/preview` 只读预览将删除的行数（含样本）；`POST /api/clean` 必须携带 `confirm=true` 才执行，按类别 / 细分代码 / 时间范围精确删除 `*_observation` 表行（宏观按 YYYY-MM、ETF/指数按 YYYY-MM-DD 比较，代码自动补零至 6 位）。删除不可撤销，但**不触发采集、不影响配置 / 监控 / 导出记录**，服务启动/重启也不会调用。
- **监控清理**：`POST /api/monitor/clean/preview` 预览、`POST /api/monitor/clean`（需 `confirm=true`）执行，仅删 `interface_run` 表；支持时间 / 状态 / 运行类型 / 类别 / 关键词组合，不影响业务数据与配置。入口在接口监控看板「导出监控」按钮之后，需二次确认。
- **输出文件视图**：`/api/files` 过滤掉 `exports/` 目录，仅展示采集生成的原始文件；导出产物仍可通过导出按钮自动下载与 `/api/download` 获取。

## 十一、Docker 部署与数据库迁移

> **新环境完整操作手册见 [`backup/导入操作说明.md`](backup/导入操作说明.md)**，含校验命令、Docker/非 Docker 两种方式、MCP 配置与常见问题。仓库 `backup/` 目录已随代码提供一份数据库备份包，clone 后即可导入。

### 为什么需要导出数据库

`output/market_data.db` 是系统唯一实时主存储，且已被 `.gitignore` 排除（采集原数据不入库）。迁移到新环境时必须显式导出，不能只 clone 代码。生产库运行在 WAL 模式，直接 `cp` 会漏掉未 checkpoint 的数据，因此必须使用 SQLite 官方 backup API 导出一致性快照。

```bash
# 在原环境导出（只读源库，不修改任何采集数据）
python3.11 tools/export_db.py --out /tmp/market_data_export

# 产物：market_data.db（单文件）、market_data.sql（可移植 dump）、manifest.json（行数/SHA256）
```

### 新环境部署步骤

```bash
# 1. 拉取代码（含 Dockerfile / docker-compose.yml）
git clone https://github.com/BeEverest/market-data-collector.git
cd market-data-collector

# 2. 解压仓库自带的备份包，创建持久化数据目录并导入数据库
tar -xzf backup/market_data_export_20261128.tar.gz
mkdir -p data
cp market_data_export/market_data.db data/market_data.db
# 校验：sha256 应与 manifest.json 中 snapshot_sha256 一致（详见 backup/导入操作说明.md）

# 3. 配置 MCP 网关（东方财富）。若新环境无法解析内网地址，可省略，
#    涨跌家数会自动降级为新浪全A快照派生，不影响启动。
export MCP_URL=https://你的MCP网关/mcp

# 4. 构建并启动
docker compose up -d --build

# 5. 验证
curl http://localhost:8000/api/health
```

### 关键约定

| 项 | 说明 |
| --- | --- |
| **数据持久化** | 宿主机 `./data` 挂载为容器内 `/app/output`。数据库、日志、导出产物全部落在此目录；重建/升级容器不丢数据 |
| **启动只读** | 服务启动/重启不清空数据、不触发采集；数据仅在看板手动采集或定时调度到点时更新 |
| **原数据保护** | 采集原表（`*_raw`/`*_observation`/`new_row_log`）只追加/幂等 upsert，不做清理删除覆盖 |
| **配置真相源** | 调度时刻、ETF/指数配置以 SQLite 为准，`config.json` 仅作镜像/种子；新环境无需重新配置 |
| **端口** | 容器内固定 8000；宿主机端口用 `HOST_PORT=xxxx docker compose up -d` 覆盖 |
| **时区** | 镜像内设为 `Asia/Shanghai`，确保定时调度按本地时间触发 |
| **MCP** | `MCP_URL` 环境变量可覆盖内网默认地址；不可达时自动降级新浪，失败明细留痕 |

### 常用运维命令

```bash
docker compose logs -f market-data              # 查看实时日志
docker compose restart market-data              # 重启（只读，不丢数据）
docker compose down                             # 停止（不会删除 ./data）
docker compose up -d                            # 再次启动
docker compose exec market-data python3.11 -c "import sqlite3;c=sqlite3.connect('/app/output/market_data.db');print(c.execute('SELECT COUNT(*) FROM etf_observation').fetchone()[0])"
```

> **注意**：`docker compose down -v` 会删除 volume，但本方案使用 bind mount（`./data`），即使误加 `-v` 也不会删除宿主机数据目录；真正删除数据需要手动 `rm -rf data/`，请谨慎。
