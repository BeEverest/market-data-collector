# 新环境导入操作说明

本目录是投研大盘数据采集系统的**数据库备份**，用于把生产数据完整迁移到新环境并继续运行。备份是 2026-11-28 11:53 从生产库一致性导出的快照（含 WAL 中未落盘的事务），共 20 张表、139,438 行。

> **核心原则**：备份里是采集原数据，只做导入和只读加载，**任何情况下都不要清理、删除、覆盖原始采集表**。服务启动/重启是只读动作，不会清空数据，也不会触发采集。

## 二、前置条件

- 新环境已安装 Docker 27+ 与 Docker Compose v2（推荐），或 Python 3.11（非 Docker 方式）。
- 能访问代码仓库 `https://github.com/BeEverest/market-data-collector.git`。
- 如需要继续采集交易类数据，需有一个可达的东方财富 MCP 网关地址；没有也能启动，涨跌家数会自动降级为新浪全A快照派生。

## 三、Docker 部署（推荐）

### 步骤 1：获取代码

```bash
git clone https://github.com/BeEverest/market-data-collector.git
cd market-data-collector
```

### 步骤 2：解压备份并校验

```bash
# 解压（得到 market_data_export/ 目录）
tar -xzf backup/market_data_export_20261128.tar.gz

# 校验数据库完整性（应输出 f5fac354...）
sha256sum market_data_export/market_data.db

# 或按 manifest 自动校验：
python3.11 -c "import json,hashlib,pathlib;m=json.load(open('market_data_export/manifest.json'));h=hashlib.sha256(pathlib.Path('market_data_export/market_data.db').read_bytes()).hexdigest();print('OK' if h==m['snapshot_sha256'] else '校验失败')"
```

### 步骤 3：导入数据库到持久化目录

```bash
mkdir -p data
cp market_data_export/market_data.db data/market_data.db
```

> 只复制 `market_data.db` 这一个文件。**不要**把 `.sql`、`.tar.gz` 或任何 `-wal`/`-shm` 文件放进 `data/`。

### 步骤 4：配置 MCP 网关（可选）

```bash
# 有可达的东方财富 MCP 网关时设置；没有就跳过这一步
export MCP_URL=https://你的MCP网关/mcp
```

未设置或不可达时，涨跌家数采集会自动降级为新浪快照派生，并在失败明细中留痕，不影响系统启动和其他采集。

### 步骤 5：构建并启动

```bash
docker compose up -d --build
```

构建过程会从 PyPI 镜像源安装依赖（默认腾讯源，海外环境可加 `--build-arg PIP_INDEX_URL=https://pypi.org/simple` 覆盖）。

### 步骤 6：验证

```bash
# 健康检查
curl http://localhost:8000/api/health

# 数据验证：应看到 etf_rows=63438 / macro_rows=3596 / trade_rows=4601
curl -s http://localhost:8000/api/status | python3.11 -m json.tool | head -40

# 容器内直接查库
docker compose exec -T market-data python3.11 -c \
  "import sqlite3;c=sqlite3.connect('/app/output/market_data.db');print(c.execute('SELECT COUNT(*) FROM etf_observation').fetchone()[0])"
```

浏览器打开 `http://localhost:8000/` 即可看到看板。

## 四、非 Docker 部署

```bash
# 1. 装依赖
pip3 install -r requirements.txt

# 2. 导入数据库（覆盖前先备份新环境现有库）
mkdir -p output
cp market_data_export/market_data.db output/market_data.db

# 3. 配置 MCP（可选）

# 4. 启动
python3.11 -u web_app.py --host 0.0.0.0 --port 8000

# 5. 验证
curl http://localhost:8000/api/health
```

## 五、关键约定

| 项 | 说明 |
|---|---|
| **数据持久化** | Docker 方式下宿主机 `./data` 挂载为容器 `/app/output`。数据库、日志、导出产物全在此目录；重建/升级容器不丢数据 |
| **启动只读** | 服务启动/重启不清空数据、不触发采集；数据仅在看板手动采集或定时调度到点时更新 |
| **原数据保护** | `*_raw`/`*_observation`/`new_row_log` 等采集表只追加或幂等 upsert，不做清理删除覆盖 |
| **配置真相源** | 调度时刻、ETF/指数/交易配置以 SQLite 为准，`config.json` 仅作镜像/种子，**无需在新环境重新配置** |
| **端口** | 容器内固定 8000；宿主机端口用 `HOST_PORT=9000 docker compose up -d` 覆盖 |
| **时区** | 镜像已设为 `Asia/Shanghai`，保证定时调度按本地时间触发 |
| **MCP** | `MCP_URL` 环境变量可覆盖内网默认地址；不可达时自动降级新浪，失败留痕 |

## 六、常用运维

```bash
docker compose logs -f market-data      # 实时日志
docker compose restart market-data      # 重启（只读，不丢数据）
docker compose down                     # 停止（不删 ./data）
docker compose up -d                    # 再次启动
```

本方案用 bind mount（`./data`），`docker compose down -v` 也不会删宿主机数据；只有手动 `rm -rf data/` 才会真正删除，请谨慎。

## 七、常见问题

**Q：启动后 `/api/health` 连不上？**
看日志 `docker compose logs market-data`。常见原因是依赖未装全（镜像构建失败）或端口被占用（改 `HOST_PORT`）。

**Q：数据行数和文档不一致？**
说明 `data/market_data.db` 不是这份备份，或启动后发生过采集写入。重新解压备份并复制即可还原到导出时点。

**Q：交易类采集报 MCP 失败？**
新环境通常解析不了内网 MCP 地址。设置可达的 `MCP_URL`，或不设置让它自动降级新浪快照。这不影响看板展示已有数据。

**Q：如何更新为新备份？**
先 `docker compose down`，备份现有 `data/market_data.db`，再用新备份覆盖 `data/market_data.db`，最后 `docker compose up -d`。全程不要删库重建。
